2D Dungeon Shooter — First College Project

BEAT THE DUNGEON

Role
Gameplay programming
Team
4 developers
Timeline
Spring 2023
Framework
MonoGame · C#

Beat the Dungeon is a 2D pixel-art dungeon shooter. You move with the keyboard, aim and shoot with the mouse, and fight through rooms of enemies that chase you or shoot at you, opening treasure chests for new weapons and artifacts along the way. The goal is to find loot strong enough to beat the boss and escape the dungeon.

Beat the Dungeon was the first project I worked on in college, and the first game for all four of us on the team. Each of us took a different part of the game. For the bare-bones prototype, I set up the player’s basic functionality and wrote a modular projectile class meant to be used by every weapon. For the finished game, I built the chests and their loot, six weapons, artifacts and potions, and the in-game HUD. Other team members built the base class structure, the camera, collisions and menus, the enemies and the boss, and the dungeon editor and dungeon manager. The knight and dungeon tiles come from free itch.io asset packs by 0x72 (opens in a new tab) and pixel-poem (opens in a new tab).

  • Projectile class — one class every weapon builds on, aimed with the mouse
  • Player — movement and a sprite that flips to face the mouse
  • Chests & loot — an enum sets each chest’s rarity and loot table
  • Weapons — six weapons built on the projectile class
  • Artifacts & potions — active abilities on a cooldown, plus health and max-health potions

Takeaways

  • Features we expected to take minutes took days, so we had to lower our scope. Randomized dungeons, a progression system and endless replayability didn’t make it in, but we got the basic loop of fighting through the dungeon working.
  • We set up one class structure early, and it held up. Because the code stayed consistent, new features were easy to add, and more than one of us could work on a bug, even in code someone else wrote.
  • Most of the time we worked separately and merged near each due date, which led to merge conflicts and late-night bug fixing. Next time I’d set our own deadlines between the official ones and actually hold the weekly session we’d planned for coding together.
